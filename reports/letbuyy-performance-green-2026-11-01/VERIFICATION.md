## What changed and why

- **Token aliases:** the stored snapshot described an earlier dark palette and omitted existing badge/banner/toast semantic aliases. The 18 violations were 7 light-theme and 11 dark-theme group/alias checks, not 18 failing components. Reviewed existing values and regenerated the snapshot using the package's documented `snapshot:aliases:update` command, as its policy explicitly requires for intentional aliases. It protects **138 duplicate-value groups**. `tokens.ts` is byte-identical to the task-start copy; no colors or shared component styles were changed to appease the validator. Original failures: [receipt](evidence/aliases-before.log).
- **A real validator defect:** the old `--self-test` passed when a stale baseline already contained violations. Hardened it to require a clean baseline, then independently reject an added alias and a new duplicate-value group in each theme. All four must produce the intended single failure. Added this self-test to `validate:ui`. Isolated replay proves the old false positive and the corrected rejection: [negative controls](evidence/guard-negative-controls.json). No rule or check was disabled.
- **Tamil layout blocking:** observed long layout work while Chromium searched native fallback fonts. Added Unicode-scoped, local-only font faces for the already-selected `TamilSangamMN` regular and `TamilSangamMN-Bold` medium/bold mappings. No font downloads or binary changes. In particular, weight 500 preserves the existing Bold face. Desktop/mobile text and SVG geometry plus actual PostScript fonts match the frozen baseline: [font parity](evidence/native-font-parity.json). A browser-only absence control removed all three local declarations and still matched the original platform fallback and layout: [fallback control](evidence/font-fallback-control.json). Platforms without these local faces retain the original generated Arial fallback and platform fallback; physical-device acceptance remains unmeasured.
- **Stylesheet delivery:** retained the established home/resource split and explicitly grouped shared font/locale/shell styles and resource styles through built-in webpack extraction. This reduces small blocking requests while keeping route styles separate and the cascade intact. Next is pinned to 16.1.6; this custom grouping must be rechecked on a framework upgrade. No CSS ordering warning was emitted. [Next CSS chunking documentation](https://nextjs.org/docs/app/api-reference/config/next-config-js/cssChunking), [webpack extraction documentation](https://v4.webpack.js.org/plugins/mini-css-extract-plugin/).
- **Below-fold work:** extended existing `content-visibility` support to the standalone plan comparison and FAQ, retaining all content, animations and intrinsic-size fallbacks. Natural scrolling, anchor arrival, FAQ open/close and same-document navigation pass. No footer/popover containment change was retained.
- **Guide imagery:** removed unnecessary unoptimized/eager loading from secondary artwork; responsive AVIF/WebP delivery and low-priority lazy loading now apply. Priority hero discovery stays intact. Explicit source aspect ratios prevent optimized image rounding from moving guide layouts. All affected views passed final rechecks after the measured subpixel shifts were repaired. Compression changes image pixels; they are not claimed to be bit-identical source assets.
- **Lint cleanup:** removed a zero-importer unused `ConnectedModules` helper and unused BookmarkButton destructuring. Converted two footer SVG image elements to equivalent unoptimized `next/image` elements with the same dimensions/source. Final ESLint and stylelint report **0 errors, 0 warnings**. Globe, motion-provider and network animation sources are unchanged.

Task-only changes, relative to the already-dirty task-start tree: [patch](SOURCE-CHANGES.patch) · [before/after hashes](SOURCE-MANIFEST.json). There are 13 changed source/configuration/snapshot files. A reverse-application dry-run passes on isolated copies. Earlier work is preserved; the patch is not a diff against HEAD and must not be blindly applied to a different tree.
