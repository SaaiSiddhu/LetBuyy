The marketing project's alias list cannot establish an Accounts binding. Binding the old names to an existing app can expose routes under an unintended hostname. The local candidate gives 200 for `/in`, a 307 for `/sdk` and `/lookup`, and a 404 for `/api` on its normal origin. Those responses show why unmatched traffic needs explicit handling. They do not predict what a future legacy hostname serves. [Prebinding Vercel checks](../evidence/vercel-proposed-domain-config.json) · [Vercel custom domain configuration](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

The recommended draft uses Cloudflare's documented redirect-only setup with three proxied A records at `192.0.2.1`, Auto TTL, two exact root Single Redirect Rules, and a WAF block for all other paths and methods on just those hosts. No new Vercel bindings are required for this design. The 301 destinations drop the original query. The guard returns the default WAF 403 and prevents origin forwarding. The proposed rules are disabled in the review JSON. The 70-case local rule matrix checks root GET/HEAD, query stripping, denied `/api`, `/sdk`, other paths and methods, and unaffected canonical hosts. Confirm the zone has a custom-rule slot and confirm the public edge returns the planned statuses before treating the scope as complete. [Draft DNS and rule values](LEGACY-EDGE-REDIRECT-DRAFT.json) · [Rule matrix](LEGACY-REDIRECT-MATRIX.csv) · [Cloudflare redirect-only setup](https://developers.cloudflare.com/fundamentals/manage-domains/redirect-domain/) · [WAF rule setup](https://developers.cloudflare.com/waf/custom-rules/create-dashboard/)

After separate authorization, refresh before-state and confirm Cloudflare edge certificate coverage for all three source hostnames. Record rule and record IDs. Stage the unmatched guard and both exact redirect rules before exposing the proxied records. Check HTTPS certificate names and chain, both HTTP and HTTPS source paths, GET and HEAD, stripped query, final 200 destinations, and unmatched paths including `/api`, `/sdk` and unsupported methods. Verify zero redirects from canonical hosts caused by these rules. On failure, remove the three new records first, then remove the new guard and redirect rules by ID. If an alternative Vercel binding was added under a later approval, remove only that new binding. Check NXDOMAIN after cache expiry and confirm canonical destinations still open. Resolve any legitimate historic deep links as a separate path mapping.

## Release boundaries

Localized editorial, legal/tax, physical-device and accessibility checks attach to the marketing pages they cover. Hold affected content for the required reviews or agree an explicitly reduced scope. The marketing release itself stays blocked by the performance gate. GA4 remains off pending a separate destination and consent approval. The buyer-app privacy/support work stays deferred. The Razorpay provider E2E remains blocked on valid Test Mode credentials. Those workstreams have separate release decisions. The live branded result, selected canonical, sitelinks and field Core Web Vitals require post-release observations.
