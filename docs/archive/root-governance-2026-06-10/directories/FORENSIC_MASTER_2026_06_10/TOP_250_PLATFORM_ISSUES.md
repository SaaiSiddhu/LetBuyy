## Methodology

- **Raw findings parsed:** **358** finding rows (prefixes TOPO 41, ARCH 38, FND 27, DB 34, PAY 32, CHK 27, AUTH 25, SEC 24, UIUX 33, THEME 22, MOB 22, PERF 32; CHK-009/SEC-019 are "control-present" informationals; AUTH-003 spans S0/S1).
- **Merge:** cross-phase duplicates collapsed into one canonical issue, preserving every source ID in the **Source IDs** column. The same root mechanism (e.g. "gateway runs as `service_role`, RLS decorative") recurs across FND/DB/CHK/AUTH/PAY; distinct *mechanisms* (table-level leak vs architectural bypass vs ledger immutability) are kept distinct and cross-referenced.
- **Unique issues after merge:** **291**. The **Top 250** are presented in the master ranked register; the remaining **41** lower-severity unique issues appear in **§ Beyond the Top 250** so nothing is lost.
- **Ranking (composite priority, V1 lens):** primary sort by a Priority Score weighted, in order, by (1) Revenue risk, (2) Security risk, (3) Data-integrity/leak risk, (4) Money-correctness risk, (5) Architecture risk, (6) UX risk; then by severity (S0 > S1 > S2 > S3). An S0 data leak outranks an S1 perf issue. Money defects that are "latent until live keys connect" are ranked high because they **block go-live**. The true go-live blockers sit at the very top and are reproduced in **§ Go-Live Blocker Shortlist**.
- Every issue carries a stable canonical ID `ISSUE-NNN` and a rank `NNN`. Evidence `path:line` is preserved in Root Cause / Source where load-bearing.

### Dominant themes

1. **"DDL-real, wiring-dead" kernels.** The hardest parts are built correctly and then *not connected*: a balanced double-entry ledger exists but legacy capture/refund/COD paths don't post to it (ISSUE-018/019/020); FORCE-RLS + tenant-GUC exist but never run under `service_role` (ISSUE-009); a reservation sweeper, a compensation executor, and a ledger-reconciliation backfill all exist as code with **zero schedulers/callers** (ISSUE-022/023/024). The failure mode is integration, not primitives.
2. **"Two parallel systems"** at every layer — two constitutions (AGENTS.md vs V1), two theme engines, two inventory systems, four money representations, four ledger families, two checkout codepaths, two staging pipelines, two session models, two audit tables, `users` vs `users_custom`. Each doubles the patch surface and breeds silent drift.
3. **RLS decorative under `service_role`.** Defense-in-depth collapses to a single app-layer ownership check on the live path; six baseline tables additionally leak to anon outright.
4. **Remediation built-but-undeployed.** Wave-0..7 "complete" claims cannot reach production because `main` is 30 commits behind and the takeover fix sits uncommitted — the deployed estate runs pre-wave code.
5. **Governance asserts a world that doesn't exist.** 187 validators / 127 governance docs enforce reserved services, dead CQRS packages, and a Helm/K8s deploy surface that never runs, while missing real drift (split apex domains, double staging pipelines). The validator loop actively *blocks deletion* of the rejected architecture.
6. **Latent money correctness gated by `[HUMAN-REQUIRED]` keys.** Every payments S1 is one config flip (`live` keys / `mode='mock'` removed) from active loss; treat the cluster as a single do-not-go-live gate.
