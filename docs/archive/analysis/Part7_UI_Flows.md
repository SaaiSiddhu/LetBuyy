## 1. Signup Flow

```
letbuyy.store → "Get Started" → accounts.letbuyy.store/signup
  → Email + Turnstile → OTP → Password → Supabase Auth → JWT cookie
  → Redirect to onboarding or admin dashboard
```

## 2. Onboarding Flow

```
ANON → CREATED → VERIFIED → CHOOSING → STORE_CREATED → SURVEYING → ONBOARDED → PUBLISHED

Steps:
  1. Choose site type
  2. Enter store name + subdomain
  3. Onboarding survey (5 questions, skippable)
  4. Create first content
  5. Review & publish
```

## 3. Admin Dashboard Layout

```
Header: Logo | Store Name | ⌘K Search | Notifications | Dark Mode | Profile
Sidebar (adaptive per site type) | Main Content Area
```

### Sidebar Navigation by Type
- **Store:** Dashboard → Products → Orders → Inventory → Coupons → Customers → Pages → AI Studio → Analytics → Settings
- **Blog:** Dashboard → Posts → Categories → Pages → Media → Comments → AI Studio → Analytics → Settings
- **Portfolio:** Dashboard → Projects → Gallery → Skills → Testimonials → Contact → AI Studio → Analytics → Settings
- **Resume:** Dashboard → Experience → Education → Skills → Certifications → Export → AI Studio → Analytics → Settings
- **Landing:** Dashboard → Sections → Forms → Pages → Media → AI Studio → Analytics → Settings

## 4. E-Commerce Cart & Checkout Flow

```
Browse → Add to Cart → Cart Page → Checkout
  → Shipping Address → Shipping Method → Payment Method
  → Payment Processing → Order Confirmation → Email
```

## 5. Order Lifecycle

```
PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED
                   ↘ CANCELLED / REFUNDED
```

## 6. Store Creation Flow

```
Choose Type → Name + Subdomain → Backend: INSERT sites → Email → Onboarding Survey → First Content → Publish
```

## 7. Trial System

- 7-day trial from store creation
- Read-only after expiry with upgrade banner
- Marketing emails at day 3, 5, 7

## 9. Component Interaction Specifications

### Button States
```
DEFAULT:  bg-primary, text-white, cursor-pointer
HOVER:    bg-primary-600, scale(1.02), shadow-md, 150ms ease
FOCUS:    ring-2 ring-primary ring-offset-2 (keyboard accessibility)
ACTIVE:   bg-primary-700, scale(0.98)
LOADING:  bg-primary-400, cursor-wait, spinner icon + "Loading..."
DISABLED: bg-gray-300, text-gray-500, cursor-not-allowed, no hover
SUCCESS:  bg-green-500, checkmark icon, 2s then revert to default
ERROR:    bg-red-500, shake animation (300ms), error message below
```

### Toast Notification
```
APPEAR:  slide-in from right (300ms) + fade-in
VISIBLE: 5 seconds (configurable)
DISMISS: slide-out right (200ms) + fade-out
STACK:   max 3 visible, new pushes older down (100ms slide)
HOVER:   pauses auto-dismiss timer
CLOSE:   X button always visible
```

### DataTable Row Interactions
```
DEFAULT:  bg-white, border-b
HOVER:    bg-gray-50, cursor-pointer
SELECTED: bg-primary-50, checkbox checked, sticky action bar appears
EXPANDED: row expands with slide-down animation (200ms), shows detail panel
LOADING:  skeleton pulse animation (3 rows)
ERROR:    error banner with retry button replaces table
EMPTY:    illustration + "No data found" + CTA button
```

## 12. Keyboard Accessibility Flow Maps

```
TAB ORDER (per page):
  1. Skip-to-content link (hidden until focused)
  2. Header: logo → search → notifications → profile
  3. Sidebar: navigation items (top to bottom)
  4. Main content: heading → interactive elements (top-left to bottom-right)
  5. Footer (if applicable)

FOCUS MANAGEMENT:
  - Modal open: focus trapped inside modal, Escape to close
  - Dialog close: focus returns to trigger element
  - Page navigation: focus moves to main heading (h1)
  - Form submit: focus moves to first error field (if validation fails)
  - Dropdown open: focus moves to first option, arrow keys navigate
  - Toast appear: aria-live="polite" announces to screen readers

ARIA PATTERNS:
  - Navigation: role="navigation" with aria-label
  - Sidebar: role="complementary"
  - Main: role="main"
  - DataTable: role="grid" with aria-rowcount, aria-colcount
  - Modals: role="dialog" with aria-modal="true"
  - Toast: role="status" with aria-live="polite"
  - Loading: aria-busy="true" on container
  - Errors: aria-invalid="true" on field + aria-describedby to error message
```
