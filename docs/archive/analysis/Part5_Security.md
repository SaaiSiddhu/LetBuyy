## 1. Authentication Architecture

### Auth Flow
- **Signup:** Email + Turnstile → OTP (6-digit, 10min, 3 attempts) → Password (bcrypt 10 rounds) → Supabase Auth → JWT (jose) → HTTP-only cookie
- **Login:** Email lookup → Password verify → Supabase session → JWT → Cookie
- **Logout:** Sign out + clear cookies + redirect

### Token Strategy
- Access token: jose JWT, 1 hour, HTTP-only cookie
- Refresh token: Supabase-managed, 7 days
- CSRF token: Double-submit cookie via CSRF_SECRET
- OTP: 6-digit, 10 minutes, single-use

### Middleware Chain
CORS → Rate Limiter → Bot Protection → JWT Validation → CSRF → Permissions → Trial Check

## 2. Security Posture

### ✅ Implemented
Password hashing (bcryptjs 10 rounds), JWT via jose, OTP verification, Turnstile bot protection, RLS on most tables, disposable email blocking

### 🔶 Partial
Rate limiting (some endpoints), CORS configuration, audit logging

### ❌ Missing (CRITICAL)
CSRF middleware, webhook signature verification, security headers, error sanitization, brute force prevention, 2FA, VPN/IP whitelist, secrets management

## 7. Security Rules (from CLAUDE.md)

15 mandatory rules enforced across all code:
1. Zod validation on every API input
2. Webhook signatures verified before processing
3. All inputs sanitized and strictly typed
4. Passwords hashed with bcrypt (10+ rounds)
5. Encryption in transit (TLS) enforced
6. CSRF protection on all mutating requests
7. XSS prevention via content sanitization
8. Rate limiting on all endpoints
9. Brute force prevention (account lockout after 5 failures)
10. IP throttling for suspicious patterns
11. Audit logs for all sensitive actions
12. Suspicious activity detection and alerting
13. HttpOnly + SameSite cookies for tokens
14. Refresh token rotation strategy
15. Token revocation mechanism
