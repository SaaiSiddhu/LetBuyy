## 1. System Architecture

```
Cloudflare DNS → *.letbuyy.store → Vercel (Next.js apps)
                  api.letbuyy.store → Cloudflare Workers (Hono API)
                                     → Supabase (PostgreSQL + Auth + Storage)
                                     → Upstash Redis (rate limiting)
                                     → Resend (transactional email)
```

## 2. Clean Architecture Layers

Presentation → API Routes → Application (Services) → Domain (Types) → Infrastructure (Clients) → Data (PostgreSQL)

**Rules:** Never put business logic in pages. Never call Supabase from components. Always validate with Zod. Always use `@letbuyy/api-types`.

## 3. Monorepo Structure

- `apps/web/consumer/` — 6 Next.js consumer apps
- `apps/web/administrative/` — 2 Next.js admin apps
- `apps/flutter/` — 3 Flutter native apps
- `backend/workers/api/` — Hono API on Cloudflare Workers
- `backend/supabase/` — PostgreSQL migrations, seed, functions
- `packages/typescript/` — Shared TS packages (api-types, ui, utils)
- `packages/dart/` — Shared Dart packages (core, models, services, ui_kit)

## 4. Tech Stack Summary

- **Frontend:** Next.js 16, React 19, Tailwind CSS 4, ShadCN/UI, Framer Motion, GSAP
- **Mobile:** Flutter 3.10+, Dart 3.6+
- **API:** Hono 4.7 on Cloudflare Workers
- **Database:** PostgreSQL 16 (Supabase) with RLS
- **Auth:** Supabase Auth + jose JWT + bcryptjs
- **Caching:** Upstash Redis
- **Email:** Resend + React Email
- **Payments:** Razorpay (India), Stripe (global), PayPal (international)
- **Hosting:** Vercel (web), Cloudflare Workers (API), Supabase (DB)

## 8. Data Flow Diagrams

### Authentication Flow
```
Browser → [letbuyy.store] → accounts.letbuyy.store/login
  ↓
User enters email
  ↓
POST api.letbuyy.store/api/auth/lookup
  ↓ (email found)
POST api.letbuyy.store/api/auth/login  {email, password}
  ↓
Hono Worker → Supabase Auth signInWithPassword()
  ↓
Supabase returns session (access_token + refresh_token)
  ↓
Worker issues jose JWT → sets HTTP-only cookies → redirects to admin dashboard
```

### E-Commerce Order Flow
```
Storefront → Add to Cart (localStorage) → Checkout Page
  ↓
POST /v1/stores/:id/orders  {items, address, payment_method}
  ↓
API Worker validates items → recalculates prices from DB → applies coupon
  ↓
Creates order (status: pending) → Creates Razorpay Order
  ↓
Returns payment session → Client redirects to Razorpay checkout
  ↓
Razorpay webhook → POST /v1/webhooks/razorpay  {signature verified}
  ↓
Order status → confirmed → Email notification via Resend
```

### Storefront Rendering Flow
```
Browser → *.letbuyy.store → Cloudflare DNS → Vercel
  ↓
Next.js middleware extracts subdomain from Host header
  ↓
Server Component → fetch store data from Supabase (SSR)
  ↓
Load active theme → resolve theme_installations → get template_data
  ↓
Render sections from theme template → inject store data
  ↓
Return HTML (ISR, revalidate: 60s) → CDN cached
```

## 9. Environment Configuration

### Required Environment Variables

```bash
# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...       # Server-side only, NEVER expose

# API Worker (Cloudflare)
JWT_SECRET=xxx                          # For jose JWT signing
CSRF_SECRET=xxx                         # For CSRF token generation

# Payments
RAZORPAY_KEY_ID=rzp_xxx
RAZORPAY_KEY_SECRET=xxx                 # Server-side only
RAZORPAY_WEBHOOK_SECRET=xxx

# Email
RESEND_API_KEY=re_xxx

# Caching
UPSTASH_REDIS_REST_URL=https://xxx.upstash.io
UPSTASH_REDIS_REST_TOKEN=xxx

# Monitoring (Planned)
SENTRY_DSN=https://xxx@sentry.io/xxx
AXIOM_TOKEN=xxx
```

### Environment Strategy
```
.env.local        → Developer machine (gitignored)
.env.development  → Development defaults (committed, no secrets)
.env.production   → Production (set via Vercel/Cloudflare dashboards, NEVER committed)
all.env.example   → Template with placeholder values (committed)
```
