Additional repairs in the current candidate:

- Read-only segment/audience/invitation/coupon previews compose caller cancellation with the existing ten-second read budget. Invitation acceptance keeps its command key and command lifetime. Best-effort remote logout has a five-second deadline before the existing local-cookie cleanup. All five new refusal/deadline regressions fail against their original wrappers; invitation acceptance still passes. The candidate passes all six.
- The editor's 433 CSS rules move unchanged into its route layout; only final blank EOF separators are trimmed. The common compiled stylesheet changes from 358,764 bytes / 49,983 gzip bytes to 299,347 / 41,645, using the same gzip level-nine tool settings. Dashboard's compiled reference graph excludes the 56,540-byte editor stylesheet; Editor includes it. This is artifact evidence, not measured HTTP transfer or visual equivalence. Editor visual acceptance remains open.
- Export no longer builds a first-100-row CSV in the browser. It starts the existing canonical job, polls with finite deadlines/backoff and a two-minute checking budget, retries the same job's status, retires old store results, and offers an authenticated streamed download. Customer export explicitly describes saved customer profiles; it does not claim to include order-only contacts or to repair profile statistics.
- The existing R2 writer failed in native workerd: an unknown-length generated TransformStream is refused. It now uploads known-length bytes with one five-MiB part buffer, sequential multipart writes and abort cleanup. Stable ID tie-breakers and live-row predicates qualify the source pages; current ownership/session store and logical expiry are checked at poll/download. This does not establish a transaction-wide snapshot, total Worker memory limit, physical object retention or hosted job durability. The existing `waitUntil` lifecycle remains.

Shared private caching, a new authentication issuer, a new read-model authority and service-role bypasses were not introduced. Existing command keys, version checks, live authorization and recovery behavior remain in place. Frozen renderer/app-extension seams remain frozen.
