**Objectives:** trustworthy gates before surgery. **Tasks:** E1 fix worker typecheck; E2 governance artifact drift; E3 CI adds gitleaks+dep audit; A4 RLS hardening migration (C1); A3 service-role confinement (C2); A6 webhook secret hashing (C4); B2 logger+no-console; secret rotation (historical all.env); B3 demo-store gate; B4 staging-URL fallback removal. **Dependencies:** P0 ratification. **Blockers:** none. **Risks:** RLS rewrite breaks first-party flows → staging E2E gate (exists: production-deploy.yml staging-e2e). **Effort:** 6–8 ew. **Rollback:** policy migrations have companion rollback scripts; logger behind env flag. **Testing:** RLS fuzz suite v1 (doc 18 §3) + existing e2e. **Ready when:** C1/C2/C4 closed, CI fully green & blocking.

## Phase 2 — Delete Dead Code
**Objectives:** execute doc 08. **Tasks:** Batch 1 (distributed-runtime/orchestration/projection-runtime + marketplace dead files) with validator pruning Batch 4; Batch 2 root decisions; Batch 3 DB drops after 30-day monitors start; Batch 5 doc archive (incl. correcting stale-claim docs); stale-doc fixes in AGENTS.md (L5). **Dependencies:** P1 (green gates prove no hidden consumers). **Blockers:** retire-vs-charter decision (P0). **Risks:** hidden dynamic imports → grep + turbo build matrix before each batch. **Effort:** 3–4 ew. **Rollback:** git revert per batch (batches = single PRs). **Testing:** full build+contract suites per batch. **Ready when:** repo minus ~45K LOC, validators consistent, root ≤10 .md files.

## Phase 3 — Build Extension Registry (+ media-service activation)
**Objectives:** persistence + ingestion for TAE. **Tasks:** migrations C-set (theme_app_extensions, files, app_versions, listing revisions, review artifacts — doc 16 §2); bundle upload endpoint + validation pipeline (doc 11 §3); media-service worker (R2 immutable paths, signed upload) per doc 19 §2; app-engine validator modules (D3 split rides along); A2 gateway route decomposition (prerequisite landed here at latest). **Dependencies:** P1 gates; P2 optional. **Blockers:** none. **Risks:** validation false-negatives → corpus tests (malicious liquid fixtures). **Effort:** 8–10 ew. **Rollback:** new tables/worker unused by runtime until P6 — deploy-dark. **Testing:** ingestion unit corpus; smoke-render harness; media-service e2e. **Ready when:** a sample TAE uploads, validates, lands in R2 with report visible via API.

## Phase 4 — Build Apps Runtime (identity + scopes + lifecycle)
**Objectives:** app identity becomes rows; APIs scope-enforced. **Tasks:** migrations B-set (oauth_clients/grants/tokens, api_keys, idempotency_keys); A1 auth strategy refactor + scope map middleware (C5); token rotation/revocation/list endpoints (doc 17 §3); A8 idempotent install + server-derived store_id; consent screen in control-plane + grant records; B7 audit events; uninstall purge job (M18); compliance challenge endpoint (H12). **Dependencies:** P1. **Blockers:** scope catalog sign-off. **Risks:** breaking existing installs → JSONB→tables backfill job with dual-read window. **Effort:** 10–12 ew. **Rollback:** dual-read keeps JSONB path alive one release. **Testing:** scope matrix tests (generated), token lifecycle tests, isolation matrix rows 1–4 (doc 18 §3). **Ready when:** app token calls `/v1/products` honoring scopes; revocation ≤60s.

## Phase 5 — Build LiquidJS Integration Layer
**Objectives:** engine extensions per doc 12. **Tasks:** namespaced `render` tag + FS map; `app` drop; filter whitelist (`app_asset_url`, money, t, image_url); per-block budgets + containment; parse-tree cache + publish precompile hook (C1 perf); sanitizer nonce-allowlist; C2/C3 perf refactors. **Dependencies:** P3 (files to render). **Blockers:** none. **Risks:** budget tuning vs real themes → shadow-render benchmarks on staging stores. **Effort:** 6–8 ew. **Rollback:** engine features flag-gated per store (feature-flags package, extracted D4). **Testing:** escape corpus, budget exhaustion, golden-render snapshots, P95 render benchmark (target ≤ today−30%). **Ready when:** sample app block renders via Liquid path under budget with assets from CDN.

## Phase 6 — Build Theme App Extensions (end-to-end)
**Objectives:** TAE lifecycle live. **Tasks:** placements/embed APIs + tables; release-manifest builder (publish pipeline, doc 13 §1); editor integration (picker, settings forms, preview-with-drafts); registry-status enforcement (H11 + edge revocation set); version pinning on installations; legacy-slot codemod + migration path (doc 12 §8). **Dependencies:** P3+P4+P5. **Blockers:** editor design capacity. **Risks:** manifest builder correctness → manifest schema + golden fixtures; theme-switch migration UX. **Effort:** 12–14 ew. **Rollback:** manifest builder versioned; resolver falls back to previous release row. **Testing:** publish→render e2e; kill-switch latency; preview drafts; placement RLS fuzz. **Ready when:** merchant places a real app's block in editor, publishes, sees it on storefront; revoke suppresses ≤60s.

## Phase 7 — Build App Blocks (`@app` in arbitrary sections)
**Objectives:** Shopify-parity positioning. **Tasks:** section schema `blocks:[{type:'@app'}]` support in theme-engine + registry; editor block-insertion UX inside accepting sections; block_order interleaving native+app; data-binding `data:[…]` fulfillment (parallelized); JSON-contract host parity. **Dependencies:** P6. **Risks:** theme authors' sections unprepared → built-in sections updated to accept @app (theme-registry change), docs for theme devs. **Effort:** 6–8 ew. **Rollback:** @app acceptance flag per theme version. **Testing:** interleave ordering goldens; data budget tests. **Ready when:** app block positioned between native blocks in hero/product sections on a demo store.

## Phase 8 — Build App Embeds
**Objectives:** head/body injection, on/off, theme-agnostic. **Tasks:** embed states API + editor toggles; manifest head/body buffers; CSP nonce pipeline + storefront CSP headers; asset conditional loading; fragment-loader island + app-proxy module (doc 13 §2) since most embeds need backend. **Dependencies:** P6 (manifest), P4 (proxy signing). **Risks:** CSP breaks existing themes → report-only rollout per store cohort. **Effort:** 6–8 ew. **Rollback:** embeds default-off; CSP report-only switch. **Testing:** pixel/chat reference apps; CSP violation telemetry; iframe-escape browser tests (C6 closure verified). **Ready when:** reference analytics embed toggles on without theme edits across both renderers.

## Phase 9 — Build Marketplace (review, versioning, billing completion)
**Objectives:** doc 14 live. **Tasks:** review queue APIs + platform-console UI; listing revisions + publish gates; B1 honest-error marketplaces; app_pricing_plans/app_subscriptions/usage-records + dunning; charge-approval UI in control-plane; install attribution + uninstall surveys; review-consolidation drops (Batch 3 leftovers). **Dependencies:** P4 (billing identity), P6 (validation gates). **Risks:** review throughput → SLA dashboard in ops portal. **Effort:** 10–12 ew. **Rollback:** review machine states additive; billing flag-gated per app. **Testing:** state-machine property tests; dunning simulation; e2e submit→review→publish→install→charge. **Ready when:** an external test app passes review and bills a dev store subscription.

## Phase 10 — Build Partner Platform (portal, Partner API, CLI, dev stores)
**Objectives:** doc 15 live. **Tasks:** partner_orgs/members + backfill from app_developers; developer-portal build-out (11 sections, doc 15 §3); Partner API router; webhook debugger (+redrive); dev stores (`site_kind='development'`); payout pipeline on Razorpay Route + statements; KYC ops in operations-portal; CLI v0 (create/deploy/dev). **Dependencies:** P9. **Risks:** payout compliance (KYC) — legal review checkpoint. **Effort:** 12–16 ew. **Rollback:** payouts manual-approve mode first. **Testing:** org RBAC matrix; payout ledger reconciliation tests; CLI e2e against staging. **Ready when:** external developer self-serves org→app→extension→dev-store→submission without staff help.

## Phase 11 — Migration
**Objectives:** legacy data → new model; ecosystem cutover. **Tasks:** JSONB oauth → token tables final cutover (remove dual-read); app_webhooks → webhook_subscriptions completion; legacy slot placements migrated (codemod stats → zero); app_developers view dropped; orphan-table drops complete; stale root docs corrected/archived; AGENTS.md + runtime-boundaries amendments merged (doc 19 §5). **Dependencies:** P4–P10 features stable. **Risks:** long-tail stores on legacy slots → forced-migration with merchant notice + auto-codemod. **Effort:** 4–6 ew. **Rollback:** per-migration companions; cutovers behind flags with 1-release soak. **Testing:** fresh-replay CI job proves chain; isolation matrix full pass; load suite (`load/` exists) on storefront render path. **Ready when:** zero dual-write paths; doc 20 §4 invariants all true.

**Objectives:** GA the platform. **Tasks:** production readiness checklist execution (doc 22); staged rollout (internal apps → 5 partner apps → open); status page + SLOs (webhook success ≥99.5%, storefront P95 ≤ baseline, review turnaround ≤5 biz days); on-call runbooks (extension kill, token mass-revoke, payout freeze); marketplace launch content. **Dependencies:** P11. **Blockers:** doc 22 gate. **Risks:** day-1 abuse → quotas (doc 15 §5) + anomaly alerts armed. **Effort:** 3–4 ew + bake time. **Rollback:** platform-level kill switches per subsystem (install freeze flag, marketplace read-only mode, embed global off). **Testing:** game-day drills (chaos/ suite exists: run extension-revoke + webhook-storm scenarios). **Ready when:** doc 22 sign-offs complete.
