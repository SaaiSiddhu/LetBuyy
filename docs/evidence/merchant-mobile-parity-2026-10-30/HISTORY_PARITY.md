# Stock history — selected-store repair and native reader

30 October 2026. Source `753734ed581da332bfb1b66def881fa6758c762a`, following core inventory `fff025100...` and its reachable Products entry `c732d0392...`. This is a source/local/database checkpoint, not a deployed feature or complete inventory acceptance.

## Defect and resulting behavior

The Gateway history route ignored the explicit `store_id`. Without a store-bound identity it returned all owned stores; with a bound identity it followed that store even when the query requested a different store. An owned database reproduction seeded two stores for one owner and a separate foreign store. The selected store had three adjustment rows, but its query returned a total of four. A mismatched bound/query store was not denied. Invalid page shapes, the staff reader and unavailable-table handling also failed their acceptance checks.

The existing canonical reader now validates its query through `InventoryHistoryQuerySchema` in commerce-core, binds explicit/session scope, checks the existing current `products:read` permission, and filters both adjustment and joined product store. Owner/staff authority remains on the server. Equal timestamps sort by ID as a deterministic second key. An empty far page recovers the same filtered total with a bounded HEAD; failed/missing counts and failed/missing history reads return sanitized 503 `INVENTORY_HISTORY_UNAVAILABLE`, never fabricated zero activity. The response acknowledges `meta.store_id`. No schema, issuer, role system or runtime was added.

`InventoryHistoryEntrySchema` is the canonical shared TypeScript row contract; the TypeScript SDK's old `InventoryEventRecord` name is a compatibility alias rather than a second row definition. Stored audit reasons have their actual eight-value contract, including `reserved`/`unreserved`; the adjustment command's input aliases remain separate. The shared Dart model preserves signed quantity changes, date, note and product/store binding. The Dart SDK exposes the existing HTTP history endpoint.

The new native Stock history screen is reachable from Inventory's shortcut and each stock row. Row navigation sends a server product filter covering all variants; “Show all products” clears it and resets the page. Previous/Next, retry and refresh use server pages. Matching totals remain unknown during loading/failure; errors do not become zero. Notes can expand and are selectable; timestamps display IST. Store/account generations retire old rows, notes, filters, counts and callbacks. Late page responses cannot replace a newer request. Missing/mismatched server scope acknowledgement is a visible unavailable state, so old backends cannot silently supply an incorrectly scoped page.
