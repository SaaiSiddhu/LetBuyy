# Reservation and receipt readers — bounded source qualification

Source `df19015379aa92472046a7d8f86ed491337ae7bd`, following history source `753734ed5` and web follow-up `1e5740f22`. This checkpoint covers read-only reservations and receipt history. Receiving commands, provider effects, staff acceptance and complete inventory parity remain open.

## Canonical contract and actual repairs

- Shared TypeScript contracts and their shared Dart mirrors describe the stored reservation and receipt records. All seven stored reservation states are supported: active, hold, committed, released, expired, fulfilled and cancelled. Location, expiry, observed positive integer quantities, timestamps and product ownership must be present. The baseline schema confirms these mandatory columns and states.
- Receipts retain their two actual families, purchase order and transfer, with matching parent IDs and store ownership. Missing quantities, invented types, malformed parents and missing counts are unavailable reads rather than fabricated zero or successful empty activity.
- The Gateway validates canonical query schemas, binds the requested/session store, excludes deleted reservations, orders tied reservation timestamps by ID and recovers matching counts for empty later pages. Receipt reads reuse `read_merchant_inventory_receipts`; there is no new database schema or parallel reader. Missing storage, failed count/RPC reads and malformed responses return sanitized 503 errors.
- Existing owner-only access is preserved. A staff `products:read` grant does not silently become authority for these owner-only routes. Positive populated controls precede foreign-store, bound-session replacement and staff-denial checks. This is not certification of every RLS attack class or staff lifecycle.
- Native Inventory now opens Reservations and Receipts. A stock row opens reservations for its product/all variants; purchase order and transfer cards open their server-filtered receipt history. Filters can be cleared. Quantities and IST timestamps are observed data; notes and references expand without issuing commands.
- Native reads pin account/store/request generation, clear private rows/counts/filters on workspace changes, reject late results and require matching store/page/count metadata. The existing history screen delegates to the same presentation lifetime and retains its previous regression tests.
- The TypeScript SDK validates the real envelope, canonical rows, page/count metadata, selected store and applied filters. It pins the same store in query and header, including a configured default store. The web BFF returns its resolved store acknowledgement after SDK validation. Web workspaces retire on account or store changes, use canonical schemas, retain applied filters while draft inputs change and preserve Previous recovery after a later-page failure.
