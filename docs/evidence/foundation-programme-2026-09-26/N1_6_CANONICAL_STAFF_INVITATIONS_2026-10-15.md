## Delivery and recovery

The existing canonical `platform_queue_jobs` stores only the invitation ID in the new `notification-jobs` / `email.employee_invite` payload. The native queue message is a signed wakeup, never the durable source. The existing queue-worker claims, completes, fails or quarantines through the323-fenced canonical RPCs. Scope mismatches/unsupported notification work quarantine; expired, revoked or consumed invitations skip without sending. Provider failure or absent access remains failed/retryable, never sent.

The worker reconstructs the proof from its purpose key, verifies the retained hash, uses the immutable message snapshot and sends through the existing infrastructure Resend adapter with `staff-invite-email:ID` as provider idempotency key. Successful API delivery requires a provider message ID. This is a provider-acceptance receipt, not inbox-delivery proof. The shared adapter now forwards the SDK idempotency option. Resend's documented key window is24 hours; the invitation expiry bounds this retry lifetime. [Primary provider engineering reference](https://resend.com/blog/engineering-idempotency-keys).

A dedicated minute cron invokes only the bounded invitation drain, recovering missing wakeups and due retries. Existing six-hour sweepers retain their schedule. Expired invitation leases are recovered using the existing canonical failure/backoff RPC, without rewriting323 or adding another claim engine. Other queue-family crash recovery remains N9 work. The minute trigger is source configuration, not an activated hosted schedule. [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/).

Actual full-worker verification exposed successful PostgREST `return=minimal` upserts being parsed as JSON. The canonical infrastructure adapter now handles successful empty minimal responses consistently with its patch path. No mock replaces this database/queue path.
