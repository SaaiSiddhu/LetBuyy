# N1.1 / N2.6 native canonical subscription catalog — 2026-10-15

The normal native pricing, payment-selection, verification, billing-recovery and current-plan summary now carry the actual Gateway catalog slug, period, amount and status. Pricing no longer enumerates the legacy trial/starter/business/professional price constants. Legacy read/API wrappers remain compatible and delegate to the same canonical checkout/verification owner; no second price or payment authority is introduced.

## Implementation

GET /payments/plans supplies explicit server-computed billing_amount_monthly_minor and billing_amount_yearly_minor using existing billing-core calculations after the store-aware founding lock. INR and integer checks fail closed. No rate or annual pricing convention is recreated in Dart. The native read model requires server amounts/currency/limit fields, preserves explicit NULL unlimited products, and rejects malformed/missing/fractional/foreign values. It reads enabled features and coming-soon/contact/purchasable flags without activating unavailable plans or the frozen ecosystem.

PricingScreen loads the selected store's owned catalog and current billing state. It displays server names/prices/limits, supports monthly/yearly selection and keeps unavailable/current plans disabled as appropriate. Keyboard/semantic selection and a review sheet remain. Changed server-versus-displayed checkout amounts require explicit review before opening payment. Load errors offer retry instead of falling back to obsolete prices. Account/store context changes hide stale plan data and refresh under the current context.

SubscriptionService's canonical checkout/verify methods accept the selected server slug and reuse the existing durable account/store retry receipts. Legacy enum-based callers delegate into that same path. RazorpayCheckoutScreen validates the returned plan/period against the selected source, uses only the Gateway-supplied key/reference, escapes options embedded in HTML and sends canonical slug/period through the shared verification endpoint. No client AppConfig key fallback authorizes checkout. This does not certify native recurring periods/add-ons/ambiguous-create recovery, which remain explicit open328 requirements.

BillingScreen uses a canonical read model instead of coercing new slugs into a legacy Trial enum. It preserves actual paid amount/cadence, failed/past-due/cancelled states and recovery eligibility. The Gateway current-subscription reader includes the latest retained nondeleted receipt, so a cancelled paid subscription stays cancelled rather than disappearing into a trial default. Billing recovery carries the actual returned plan and period into the same payment screen. A storefront payment-config badge no longer represents the unrelated platform subscription provider; unavailable platform provider state is shown honestly. Settings' current-plan summary reads the same billing state. Broader legacy product-usage/provider entitlement gates remain N2.6/N2.2 work and are not certified by these presentation changes.
