## Canonical implementation

The existing billing_history platform-charge owner holds the pending checkout, original actor/store/active plan snapshot, billing period, amount/currency, coupon/provider input and response terms. No order is fabricated and no new payment registry, ledger or money balance is added. A private claim RPC creates that pending row and its existing idempotency_keys receipt atomically before outbound provider creation. The invoice row retains the logical checkout key after activation. Same-key request changes are conflicts; current ownership is checked before any saved quote is returned. Storage absence/errors fail closed, without the generic idempotency adapter's missing-schema fallback.

Only the successful initial claimant may POST the provider create. An ambiguous response never authorizes another POST with that key. Order recovery uses the existing infrastructure adapter's exact-receipt lookup, bounded to two objects, and requires exactly one returned object matching receipt, amount, currency, checkout ID, store and account metadata. Receipt is sub- plus the immutable UUID (40 characters). Missing, ambiguous or mismatched results remain503 pending. A late successful create can still bind the same source; binding rechecks current ownership and refuses changing an already bound reference. Native-subscription creation is retained and source-bound, but an ambiguous native create deliberately remains pending for provider reconciliation; automatic native discovery is not claimed.

Verification uses the shared provider-payment-verification authority, extended to the existing billing-core native subscription HMAC payload. Order payload construction delegates to billing-core too. The saved source supplies activation plan/entitlement/price terms; verify no longer reprices against a later catalog/founding/coupon state. Captured payment ID, status, currency, exact amount and mandatory order reference must match. Trusted callbacks also use the saved plan; a mismatched amount is rejected atomically. An existing retained paid receipt may be read back without authorizing a new purchase.

Activation finalizes that same pending billing row with its paid subscription, provider-payment reference, invoice fields and period, in the existing327 transaction. Native contract source retention permits subsequent invoices while preserving the global captured-payment fence; complete native recurring/add-on/provider behavior remains an explicit unverified scope below. Stripe, free activation and explicit sandbox AutoPay interfaces retain their existing dispositions.

Additional writer guards on subscriptions and billing_history require the canonical backend role or the owning database role, including when a legacy permissive policy/grant survives. Existing owned SECURITY DEFINER financial functions remain eligible. Backend-only quote SELECT policy excludes quote records from ordinary Data API reads. RPC ACLs remain service-only. These guards are defense in depth; broad legacy billing read privacy outside quote records is not certified by this patch.
