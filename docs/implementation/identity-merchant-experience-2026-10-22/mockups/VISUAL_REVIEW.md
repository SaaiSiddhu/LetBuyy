# Mockup review and implementation limits

22 October 2026 · Built-in imagegen · Original visual proposals with fictional records.

Review separates three questions: does a board communicate its proposed pattern; does it contain desktop/tablet/mobile; and has that behavior been implemented or tested? Only the first two can be assessed from these images. The third remains a source/browser acceptance task.

## Required visual review

- Each final board must show three labeled views, with a complete mobile frame and readable principal actions.
- White/neutral work surfaces dominate; plum identifies chrome and decisive actions. Semantic statuses remain distinct.
- Navigation feedback, dirty work, overlays and errors need state examples, not only a single polished screen.
- Main merchant and Settings dirty SaveBars use the same recipe. Editor commands, bulk selection and promotions have their own responsibilities.
- No generated control enables frozen apps, a new issuer/provider, remembered-device authentication, autonomous publication or unapproved money movement.
- Incidental copy, navigation entries, API capability, schema limits and fixture values are not promoted to current product truth.

## Pixel and test boundaries

Generated rasters are concept boards. The prompt requested a large landscape canvas; actual file dimensions are recorded per board in the manifest. Viewport labels1440/768/390 are CSS design references inside the presentation, not raster-sized browser captures. They are not pixel-parity evidence. Exact hex values, font files/metrics, controls, icon paths and breakpoints must come from [the written system](../03_PREMIUM_PURPLE_SYSTEM.md) and existing canonical tokens/components.

Visual inspection does not prove keyboard order, ARIA/landmark semantics, contrast for every composite, touch targets, screen-reader announcements, safe-area/keyboard behavior, server authority, save success, network retry, latency or end-to-end completion. Those remain the [implementation handoff](IMPLEMENTATION_HANDOFF.md) and [test plan](../05_TEST_AND_COVERAGE.md). No application test result is credited to image generation.
