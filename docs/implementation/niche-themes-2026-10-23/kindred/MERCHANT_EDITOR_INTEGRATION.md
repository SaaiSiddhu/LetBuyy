# Kindred merchant editor integration

`KindredFactsEditor` is implemented at `apps/merchant/web/src/components/products/niche-facts/kindred-facts-editor.tsx`. It consumes the existing `NicheFactsEditorProps` contract and the public canonical domain schema/helpers. It uses host `Button`, `Input`, `Select`, `Textarea`, semantic tokens and `React.useId`. It creates no network, storage, form, new domain DTO or persistence path.

The six mounted component tests exercise actual edited payloads, invalid intermediate rows and quantities followed by correction, duplicate/invalid category keys, omitted optional facts, deliberate clear, actual product image choices, missing selected images, disabled controls, no parent form submission, unique labels and inert hostile text. Focused TypeScript and ESLint checks pass. This evidence does not establish durable merchant save, authorization, conflict recovery, browser layout or published buyer data.

The parent integration remains owned by the shared product-form writer:

1. Pass only the controlled `metadata.gifts` draft as `value`. Keep raw incomplete values editable; do not replace a failed parse with empty/default facts. `null` means explicitly delete the namespace. An untouched unknown namespace remains omitted; never persist `gifts: null`.
2. Merge the child callback into the existing product snapshot/draft/conflict/version/idempotency lifecycle. Preserve unrelated metadata through the established owner. Before saving, validate `GiftFactsSchema` and the effective-image invariant through the canonical product command. Use parsed data only after success; show/focus the parent validation failure without losing raw input.
3. Pass the current draft `images` and `variantOptions` as `resources` and the actual parent read-only/submitting/session permission state as `disabled`. Image options refer to that exact image order. Missing images stay visible for correction; the child does not guess a replacement photograph.
4. For implicit image-only edits, the canonical server writer must call `rebindGiftMediaRoles(existingFacts, oldImages, newImages)` on the old authoritative facts. Exact unique URL matches preserve/reorder roles; removed/ambiguous roles clear. Persist the merged product atomically. An explicit merchant role assignment must validate against effective images. The parent must preserve that intent distinction when serializing a full metadata snapshot; unchanged role indices must not silently become a different view after a reorder.
5. Include the gift draft in the existing pending-operation snapshot and conflict comparison so recovery retries the same authorized intent/version/key. The child neither starts a fresh command nor promises cross-route retention.
6. Verify the mounted parent create/edit/clear, stale version, permission loss, failed/uncertain save/retry, image replacement/reorder and published buyer output using synthetic fixtures before claiming the lifecycle complete.

Image schema probes are reproducible with `node --import tsx docs/implementation/niche-themes-2026-10-23/kindred/kindred-media-write-probe.ts`. Valid create/update controls pass; supplied out-of-range references are rejected. The separate helper tests cover implicit edits; a paired migration file alone does not prove its real database persistence.
