# Playfield collection/search query continuity correction

Circuit's independent audit correctly found dropped `limit`, `country_of_origin`, repeated connector values and unrelated filters in independent clears. The earlier Playfield helper used `Object.fromEntries` over controls, which collapsed repeated values and missed this defect. That helper is replaced with actual native DOM `FormData`, then `URLSearchParams` and the canonical `storefrontDiscoveryQueryFromEntries` / `StorefrontDiscoveryQuerySchema` parser. No query schema or backend filter algorithm is copied.

Only the owned discovery module, factory and tests changed. The fixed query-key lists and manual clear forms are removed. Each GET form iterates `collection.discovery_query_fields` once per supplied row, preserving repeated values. It excludes `page` and only controls edited by that form: search; search/sort plus each rendered age/interest chooser; or the rendered homepage finder choices. A conditional chooser that is absent leaves its active query field hidden. The owned factory adds search-only preservation to its cloned inherited search-box source; the shared base section is unchanged.

Every active filter, including non-toy fields and each selected connector, renders the exact `collection.active_filters[].clear_url`. Clear-all uses `collection.clear_filters_url`. Pagination/reset semantics and all other values remain the canonical URL helper's responsibility. A valid active value absent from current facet choices is retained as the selected current value only inside an independently supported chooser. It never enables a missing capability. Supplied capability gates, options, ordinary search/sort fallback and trusted no-network demo behavior are preserved.

`query-continuity-tests.tap` has **37/37 passing targeted cases**: theme13, discovery/form15, actual source/manifest3 and app mapper6. Seven new form cases cover collection/search native submissions; limit/country/repeated values; search/sort changes; every independent clear and single-connector removal; conditional absent choosers and zero results; metadata-free basic queries; chooser changes/blanking without duplicate scalars; current selections missing from supplied choices; and trusted demo refusal of unsupported discovery. Several concerns share a case. The entire harness is guarded against fetch and observes zero network calls. The engine and focused harness TypeScript checks pass; owned discovery-module/test ESLint exits zero with only configuration environment notices.

`query-continuity-receipt.json` pins exact changed-source and dependency hashes. Neither the Circuit oracle nor its generated reports were edited or run by this chat. A concurrent source change from the baseline SHA256 `dc5d7cbc5ec8f23fb91275ef881ad5aabe2729913a51e968e67636fe9e708f31` was observed and reported to the coordinator; both read checkpoints are recorded in the receipt. The coordinator/Circuit owner should rerun the unchanged full audit after owner handbacks. This handoff does not claim all other themes pass that independent oracle.

All 113 frozen M1 artifacts and archived captures remain unchanged. Older receipts remain historical checkpoints, superseded for current source hashes by this receipt. No backend/shared index, runtime normalizer, parent page, browser/DB, build, migration or deployment work was performed. The parent writer lease remains released. These are in-process render/query proofs, not browser hydration or live SQL acceptance.
