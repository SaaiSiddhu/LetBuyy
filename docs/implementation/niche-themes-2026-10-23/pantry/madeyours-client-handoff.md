# MadeYours client checkpoint · 23 October 2026

The five files in `madeyours-client-source-freeze.json` are frozen and explicitly released to the coordinator. The client reuses the existing `bindMadeYoursPersonalization`, canonical domain validation, storefront browser proxy, cart mutations and saved-snapshot formatter. No backend, ProductService, compositor, domain schema, SQL or other factory was edited in this slice.

The native add-to-cart element obtains a no-store server context scoped to exact product and selected durable variant (explicit null for an unvarianted product). It validates the canonical schema and exact returned IDs; keeps base eligibility separate; requires another explicit review after text/method/style/placement/variant/product changes; requires NFC suggestion consent; and aborts/discards late selection/product/disposal responses. Context failure blocks review/purchase and exposes retry. Disconnect/reconnect removes prior behavior and never restores an old review. Trusted catalog conversion remains fully inert with zero review/cart requests.

Only the canonical `PersonalizationCartDraft` crosses the cart boundary, containing exact text/choice IDs plus facts revision and the opaque server fingerprint. No client digest, product version, price or accepted labels become authority. Different configurations stay separate, identical drafts merge locally, and receipt line IDs/configuration/snapshot fingerprints plus the validated saved snapshot and canonical draft survive rehydration. Quantity/removal target exact receipt IDs; strict mutation input resends untouched canonical drafts and adds no line.id field. Accepted text/labels render through the existing saved-facts formatter and HTML escaping, never generic properties or telemetry. Aggregate stock remains server-enforced.

Personalized adds await a server receipt. A transport retry resends the prior intended quantity rather than incrementing it again. Stale/personalization or inventory rejection restores only its unchanged optimistic cache, refreshes context and requires a new review. Cart mutations serialize; a delayed receipt supplies the cart token without replacing newer local lines, and the next mutation retains both configurations. This is client behavior, not proof of server idempotency or SQL execution.
