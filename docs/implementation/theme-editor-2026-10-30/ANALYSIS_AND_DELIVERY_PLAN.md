# Theme editor: Shopify observation, LetBuyy audit, and delivery plan

Date: 30 October 2026 (Asia/Kolkata). Owner request: inspect the current Chrome Shopify Horizon editor first, then complete LetBuyy's one canonical editor across ten included themes. This is a current source and UI audit, not a runtime or release certificate. No Shopify settings were changed or saved during inspection.

## 1. What was directly observed in Shopify

The current Chrome profile had an active **Horizon** theme open in Shopify's editor. The user-supplied nine screenshots and a read-only inspection of that same editor establish:

| Capability | Direct observation in this account | Design implication |
| --- | --- | --- |
| Workspace | Theme identity and Active state, top template picker, inspector toggle, mobile preview, undo/redo, Save, left structure panel and live preview. Save/undo were disabled in the clean state. | Keep theme/revision/dirty status and actions persistent without obscuring preview. |
| Structure | Header, Template, Footer groups; Announcement bar has an Announcement child; section and block rows expose reorder, hide and remove actions. Featured collection showed nested Header and Product card parents with editable children such as Collection title, View all button, Media and Product title. Its static parents had disabled reorder handles. | One document tree with stable section/block instance IDs, legal nesting, static-versus-merchant-owned rules and group ownership. |
| Template navigation | The picker lists Home, Products, Collections, Collections list, Gift card, Cart, Checkout/accounts, Pages, Blogs, Blog posts, Search, Password and 404. Opening Pages showed Default page and `contact`; choosing `contact` loaded the `/pages/contact` preview, a Contact form section and `Assigned to 1 page`. A separate preview picker listed the Contact resource. Blogs had Default blog. Blog posts had a disabled default because this account had no posts. | Template key and preview resource are distinct; selecting a page changes both editing context and rendered content without changing its assignment. Empty categories need honest states. |
| Inspector | Preview outlines and insertion controls align with the selected section; the selected section opens its settings. The user screenshots show plus buttons at section boundaries. | Preview click and tree selection must agree on exact instance and insertion position. |
| Add section | The chosen insertion point opens a searchable catalog near that point, with theme-specific categories and visual preview. | Settings | The Announcement bar inspector displayed timed announcement, width, palette color, divider and padding controls, plus section-level Custom CSS and removal. Global settings exposed 19 groups from Logo and favicon through Theme style. | Every shown field must round-trip as its declared type and visibly affect its own scope. |

These are observations of this Horizon/account state, not proof of Shopify's private implementation or persistence. Shopify's public contracts describe theme/section/block settings, limits, presets, and inspector insertion behavior: [features](https://help.shopify.com/en/manual/online-store/themes/customizing-themes/theme-editor/features-overview), [inspector](https://help.shopify.com/en/manual/online-store/themes/customizing-themes/theme-editor/preview-inspector), [section schema](https://shopify.dev/docs/storefronts/themes/architecture/sections/section-schema), [settings](https://shopify.dev/docs/storefronts/themes/architecture/settings). Accessed 30 October 2026. This account had no blog posts to inspect and no Shopify mutation was performed; Shopify undo, save, publication, conflict and recovery outcomes were therefore not exercised.

## 2. Current LetBuyy source path

`apps/merchant/web/.../editor/page.tsx` loads the store/theme draft and package-derived schemas via the Merchant editor API, builds a single editor state, and uses `ThemeDraftClient` for versioned save/publish. The shared `packages/theme-engine` owns the bundle, template registry, section/block schemas, document and preview protocol. Gateway theme routes provide store-scoped draft, publish, signed preview, immutable releases and rollback. Commerce loads the preview or frozen published Liquid bundle. The published render reads `theme_releases.template_snapshot.liquidBundle`; editing a builder source file does not update an existing published store.

The current first-party builder generates **2.1.0** source bundles for all ten retained slugs. A source-only execution found 23 template definitions and 45 section definitions in each (Habitat 46), with one reusable block definition. Definitions are not proof that every section is legally insertable, installed in the database, or visible in a published release. The 23 keys include distinct `page`, `blog`, and `article`. Historical bounded local editor cycles covered all ten, but the last recorded programme handoff issued **zero full-theme certificates** and cannot stand in for current-source acceptance.

## 5. Ordered implementation and verification

1. **Freeze evidence and ownership.** Reconcile current `develop`, dirty files, installed catalog/migrations, active writer leases and prior sealed patches. Create an isolated source-complete candidate; preserve the current checkout and synthetic fixture. Obtain a bounded writer allocation for shared editor/engine paths under the programme's ownership rules.
2. **Make the canonical contract complete.** Add an insertion intent and legal-candidate query to `theme-engine`; validate group, template, parent, order, limits and unique IDs in gateway/document logic. Keep one draft spine and one Liquid renderer. Implement a safe decision for Custom Liquid before any UI affordance.
3. **Finish merchant interactions.** Contextual section/block catalogs anchored to tree or preview insertion points, category/search/preview, grouped template/resource navigation, exact block inspector, property scope and responsive layout. Build loading, empty, failed, permission, conflict, offline and unsaved-exit states around acknowledged server responses.
4. **Connect content and public render.** Pages, blog listings, individual articles, menus/media, products/collections and dynamic bindings must resolve tenant-owned content; preview must match selected template/resource; published releases must render the exact saved version. Carry metadata/canonical URLs, sanitization, performance and accessibility through the public output.
5. **Qualify by increasing blast radius.** Unit/contract for schema and UI actions; owned PostgreSQL and real mounted Gateway for authorization/CAS/RLS/rollback; Liquid SSTI/XSS/render-budget and parity suites; browser merchant→signed preview→release→anonymous storefront; then ten separate niche matrices and provider Test Mode only where relevant. Use one owned fixture and explicit preservation/no-reap mode. Do not reuse protected stores or infer financial settlement from test captures.
6. **Independent closeout.** Run relevant build/governance gates in a disposable source-complete snapshot, inspect mobile/narrow screenshots, reconcile failure receipts, and issue one certificate per theme only after its original matrix passes. Local qualification, staging, production and real-provider operation remain separate verdicts. No push, merge or deployment follows from this plan alone.

## 6. Immediate next execution slice

The smallest load-bearing start is **ED30-01 plus ED30-03**: position-correct section insertion and stable preview device switching. Before source edits, compare the current dirty editor files with the sealed preview proposal and obtain the current writer/fixture allocation. Then run a real Threadline page and one other niche theme through add-before/after in Header/Template/Footer, exact save/publish/readback, and three viewport modes. This creates a trustworthy base for the broader ten-theme matrix.
