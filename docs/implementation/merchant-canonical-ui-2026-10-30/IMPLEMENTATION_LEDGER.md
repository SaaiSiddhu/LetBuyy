1. **Persisted notification inbox:** Merchant GET now resolves an owned store, validates bounded pagination with Zod, and reads the canonical user-scoped gateway inbox plus account unread count. Failure of the optional count does not turn a successful list into a false empty state. POST delegates read-all to the gateway and then the client reloads persisted state. No client-only read mutation remains.
2. **Real navigation:** the header dropdown links to `/{store}/notifications`; a full page provides loading, empty, error/retry, paged results, and account-wide scope copy. The old fabricated Orders/forms feed was removed from this control.
3. **Honest shell controls:** removed Settings route-count badges that mislabeled static route metadata as availability, and hid the Settings assistant trigger while that panel is unavailable in the Settings composition. The remaining non-Settings trigger still opens the existing panel. Sidebar collapse preference handles storage failure.
4. **Functional icons:** Merchant primary navigation icons now use Lucide through the shared UI package, preserving grey and active hierarchy. The old SVG masks are deletion candidates, not yet removed.
5. **Artwork delivery:** shared Merchant empty-state art now requests lazy, optimized Next images instead of eager, original-size PNG delivery. Actual production transfer has not yet been measured.
6. **Header and Settings recovery:** sign-out checks the local logout response and reports failure instead of redirecting after a failed cookie-clear attempt. Successful navigation uses the configured Accounts lookup URL. The account switcher exposes the existing theme controller so content dark mode is reachable. Phone header sheets use the shared UI focus trap, dialog semantics, Escape dismissal, trigger focus return, and controlled/expanded attributes. Settings search now reports no matches.
7. **Two dead control repairs from the static audit:** the command palette’s inert filter button is now a decorative Lucide icon; its functional category chips remain. The theme update warning now links to the existing theme library duplication workflow, rather than presenting a button with no handler. The update’s conflict acknowledgment gate remains in place.
8. **Products test alignment with current workspace:** concurrent Products-page work moved manual refresh into its filter popover. The status recovery tests now exercise that reachable action and identify the status selector by its full accessible name. The mutation/idempotency assertions were retained.
9. **Command palette access:** search, close and result icons now follow the Lucide web rule; actual result rows are shared `Button` controls with a named dialog, focus trap, combobox/listbox association, and keyboard selection. The former clickable `<div>` rows had no native focus or action role.
10. **Truthful live search:** the command palette now sends the product query to the owned-store API, keeps successful entity results when a sibling resource fails, distinguishes a partial or total live-read failure from a genuine no-match, and offers a retry. Product, order, and customer matches navigate to their detail route when a stable record key is present. Stale store/query results remain scoped out.
11. **Frozen Apps projection:** the server's fail-closed app-platform flag is passed into the canonical navigation projection. With the flag off, the main sidebar, Settings sidebar and dashboard, command palette, category chip, and `g x` shortcut omit the Apps route that otherwise responds with 404. 12. **Collapsed rail touch access:** at tablet/desktop sizes without hover, tapping a collapsed item with children opens its existing rail submenu. Outside pointer dismissal closes it; the parent route remains available as the submenu heading link. Touch and tablet browser acceptance remains open.
13. **Assistant claim:** the setup assistant now says only its loaded checklist is complete, rather than declaring the entire site ready from those six checks. Its functional controls use shared Lucide icons. An additional component test covers the fully checked wording; this is not provider or launch-readiness evidence.
14. **Search result identity:** command result rows now use destination plus position for React keys, so two live records with the same display name do not collide. The sidebar drawer focus branch uses explicit control flow; its accessibility behavior is unchanged.
15. **Notification recovery truth:** a failed inbox read after a persisted mark-all update no longer claims notices were unchanged. An unconfirmed write response asks the merchant to refresh before retrying. Two component regressions distinguish these states.
