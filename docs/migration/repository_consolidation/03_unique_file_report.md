# 03 — Unique File Report and Classification (Phase 1 input)

## Part 1 — unique files (the third category from doc 02's hash analysis)

Of the 6,176 files hashed across the three trees, **4,520 have a content hash that appears nowhere else in the hashed universe** — genuinely unique content, not a duplicate of anything in A, B, or C. That is 73% of everything hashed. This is expected and healthy: most of a real application is unique business logic; the 27% duplication found in doc 02 is concentrated in scaffold/template files, not spread evenly through the codebase.

No further action is implied by "unique" alone — uniqueness does not mean "correct" or "keep"; it just means no byte-identical twin exists elsewhere in this hashed universe. Determining which unique files are live vs. dead is Phase 1/2 work (see doc 04 for the survivor judgement on whole apps).

## Part 3 — `.env.local` inventory (untracked in all three repos, confirmed)

`git ls-files | grep -E '\.env(\.local)?$'` returned **empty in all three repositories** — no `.env.local`/`.env` file is tracked by git anywhere in this workspace. 13 `.env.local` files exist on disk (1 System A root, 1 `admin-web`, 1 `store/storefront`, 1 `Agrimore/legacy_archive_v2/apps/marketplace-web`, 8 System C apps sharing an apparently-common 65-variable local-dev template — `identity-platform`, `merchant-control-plane`, `storefront-runtime`, `app-marketplace`, `marketing-site`, `platform-operations-portal`, `platform-console`, `developer-portal`). All 13 have distinct SHA-256 hashes (no two are byte-identical, despite the 8 System C files sharing the same 65 variable *names*).

Variable-name-only classification (no values read into any output beyond a length/pattern heuristic that never displays the value itself): the 8 System C files each carry 65 variables, of which 5 are empty, 6 match an obvious-placeholder pattern (`your_`, `xxx`, `changeme`, etc.), and **42 hold opaque, populated-looking values ≥20 characters with no spaces** — including `AUTH_SECRET`, `CUSTOMER_SESSION_SECRET`, `STRIPE_SECRET_KEY`, `RAZORPAY_KEY_ID`, `RESEND_API_KEY`, `LETBUYY_IDENTITY_PRIVATE_JWK`. **Whether these 42-per-file values are live/production-scoped or shared dev/staging fixtures was not determined** — determining that would mean either reading the value (an explicit prohibition beyond type classification) or querying a live provider (explicitly out of scope for this phase). Marked **UNKNOWN**, flagged for the owner: these files are not committed to git, but they exist unencrypted on local disk and should be confirmed dev-only before this workstation is considered a low-risk location for them.

## What this document proves and does not prove

**Proves:** an exhaustive, byte-measured breakdown of where the 32 GB actually is (dependency caches and — overwhelmingly — five Agrimore `build/` directories, not source); that `.env.local` secrets exist only outside git in all three repos; the exact list of hardcoded, committed secrets found (cross-referenced with doc 05).

**Does not prove:** that the ~0.4 GB "real source" residual is entirely necessary going forward — some of it (the `store/web` empty directory, some of `legacy_archive_v2`) is very likely prunable, but Phase 0 makes no deletion and draws no such conclusion here; that determination, and the actual pruning, is explicitly Phase 1+ scope.
