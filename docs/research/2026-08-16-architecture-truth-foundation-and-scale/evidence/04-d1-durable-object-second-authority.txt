# D1 + Durable Object: is there a SECOND data authority? (first-hand, 2026-08-16)
# Evidence state: VERIFIED-SOURCE + VERIFIED-CONFIG

## The constitutional question
DOC 01 R-15 / ART-04 require ONE PostgreSQL source of truth. services/api-gateway/wrangler.toml
declares, in env.production, a D1 database and a Durable Object namespace. If either held
durable business state, that would be an accidental second data authority.

## VERDICT
D1 and Durable Objects are NOT a second data authority. R-15 / ART-04 are NOT violated on
this axis. The one-PostgreSQL invariant holds with respect to D1 and DO.

## BUT — three real secondary findings
1. DECLARED-BUT-UNUSED PROVIDER RESOURCES. A real D1 database_id is committed and a DO
   namespace is bound in production for infrastructure that no code path uses. This is
   ANTI-R7-adjacent (the estate declaring something it does not use) and carries a small
   ongoing provider cost.
2. A VALIDATOR ENFORCES THE DEAD INFRASTRUCTURE. scripts/validators/durable-object-validator.mjs
   lines 17-18 assert that wrangler.toml contains new_sqlite_classes = ["LetbuyyRuntimeDurableObject"]
   and that index.ts exports the class. The validator suite therefore actively REQUIRES this
   unused capability to remain. This is a concrete, citable instance of the gate enforcing
   something that is not a constitutional invariant (ART-02 / ANTI-R3 concern).
reporter.assert(apiWrangler.includes("[[migrations]]"), "API Gateway wrangler must declare Durable Object migration");
reporter.assert(apiWrangler.includes(`tag = "${topology.durableObjects.migrationTag}"`), "Durable Object migration tag must match topology");
reporter.assert(apiWrangler.includes('new_sqlite_classes = ["LetbuyyRuntimeDurableObject"]'), "Durable Object must use SQLite-backed class migration");
reporter.assert(indexSource.includes("export { LetbuyyRuntimeDurableObject }"), "API Gateway main module must export Durable Object class");
reporter.assert(durableSource.includes("blockConcurrencyWhile"), "Durable Object must initialize storage through blockConcurrencyWhile");
reporter.assert(durableSource.includes("checkpoint"), "Durable Object must expose checkpoint state for rollback recovery");
3. FUTURE BOTTLENECK RISK. A single Durable Object serialises all requests addressed to it.
   The name RUNTIME_COORDINATOR invites future promotion to a real coordination role; if that
   happened, it would become a hard single-threaded ceiling on whatever it coordinates.
   Safe today ONLY because nothing calls it.
