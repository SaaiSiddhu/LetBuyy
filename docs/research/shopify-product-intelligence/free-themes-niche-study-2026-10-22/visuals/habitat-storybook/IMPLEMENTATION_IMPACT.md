## Minimal facts and query contract

This is the semantic requirement, not an approved SQL schema or a new domain model. The coordinator's shared facts/query writer decides the physical representation after inspecting current persistence. No variant-metadata column is assumed to exist.

1. **One bounded furniture namespace** owned by `commerce-core`, schema-validated on merchant write and again on public projection. Expose only allowed material/finish/assembly/care data. Missing facts are absent/unknown; zero is not a missing-value substitute.
2. **Explicit dimension semantics:** assembled width/depth/height, optional round diameter and seat height; separate package width/depth/height; supplied product/package mass only with its meaning and unit. Normalize supported source units to one server comparison unit (proposed millimetres/grams) and format readable centimetres in the theme. Input bounds/precision and supported units belong to the shared contract, not arbitrary theme JavaScript. For a round table, normalized maximum footprint width is its supplied diameter, not an invented rectangle.
3. **Common facts + actual variant overrides:** resolve by durable product/variant ID. The finish label is the actual option identity, never a matching heuristic based on color. Keep common assembled dimensions when an override is absent; update real variant-specific dimensions/package/weight/image/price together. Product metadata already persists; the mechanism for atomic per-variant facts and new-variant ID mapping is a concrete gap for the shared writer, not silently solved by this inventory.
4. **Bounded text:** material, assembly status (`assembled`, `assembly required`, `not supplied` semantics), merchant instructions/tools/care and actual policy reference. Sanitize and bound text. Do not infer material, certification, weight capacity or a service from a photograph.
5. **Discovery:** page/limit; room/type via actual collection/category bindings; maximum assembled width/depth/height with explicit units; permitted material/finish filters; existing supported price/sort semantics. Preserve all selected supported keys through browse, clear-one, pagination and browser back. Return real total/has-more. Apply dimension + finish predicates to the same available SKU/effective facts, not different variants of one product.
6. **Quote/policy:** use existing eligible rates, address and actual merchant service conditions. No delivery date/window is required for launch merely to fill space: show unavailable until a trustworthy server result exists. AR, room planning, custom manufacturing and assembly scheduling stay excluded (E). Any actual service/date promise is D, owned by shipping/checkout and the merchant.
7. **Order history:** if measurement/finish facts are displayed, preserve their accepted version in the existing canonical immutable product/variant line snapshot. Extend the bounded buyer projection/client contract. Never make an order row editable, expose private snapshot fields, or use mutable current product metadata for old-order dimensions.
