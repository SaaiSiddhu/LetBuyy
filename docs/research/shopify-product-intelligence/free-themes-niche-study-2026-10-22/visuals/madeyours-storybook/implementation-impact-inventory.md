## Decisive findings

1. **Both gateway and Liquid cart merge by product/variant.** Gateway `lineId()` does not use `properties`; `buildCartLines()` aggregates on it. The Liquid island uses the same product/variant match. Sending Asha and Kabir as generic properties would merge them. Quantity/remove also address product/variant, so display changes alone cannot fix the workflow.
2. **Nested generic properties are not a durable configuration contract.** Cart wire schema accepts arbitrary `properties`, but the Liquid server-to-client adapter retains string-valued entries only. A nested configuration can disappear in browser readback even if the cart row stored it.
3. **The signed digest ignores configuration.** `CheckoutCartBindingLine` and `canonicalCheckoutCartBinding()` include product/variant/listing/quantity/amounts, not the accepted specification. Configuration must join that same canonical binding; no second signing system.
4. **Hosted checkout drops configuration before the order RPC.** `checkoutOrderItems()` creates product/variant/listing/quantity commands. `CheckoutOrderItemCommand` has no configuration. The lower inventory writer constructs each order-item snapshot from its own bounded field list, so merely adding a field to an outer request does not persist it.
5. **Readback has several deliberate allowlists.** `normalizeOrderItemRecord()`, buyer-realm order projection, Liquid customer drop and merchant order UI omit configuration. Add only a validated public/owned configuration projection; never expose the full product snapshot/private metadata to make text appear.
6. **Nova is still general Core v1.** A read-only catalog-factory evaluation returned stable `letbuyy-nova`, UUID `7b669c70-0000-4000-8000-000000000009`, name Nova, category General and package 1.0.0. Core compatibility repair recognizes every first-party slug except the explicit Sense-v2 carve-out. A distinct Nova-v2 package also needs correct version-aware repair exclusion.

A read-only call of the existing canonical binding with otherwise-identical synthetic cart lines confirmed the same binding string for Asha versus Kabir nested properties; neither text appears in the binding. This is a pure-function contract probe, not worker/DB/handoff acceptance. The first implementation tests must demonstrate each failure through the actual relevant consumers before fixing it.
