## Test classes and release gate

Use `AGENTS.md:201-216` Theme-Liquid full rigor: unit, integration, contract, E2E, security, performance, regression, rollback validation, deletion validation where a deletion occurs. Validator green is insufficient without buyer behavior. `packages/theme-engine/test/*`, Merchant theme-editor tests, Commerce Liquid tests and gateway owned-DB tests are candidate suites; inspect their exact assertions and run results at the future candidate revision. For each section port, compare Liquid and React DOM/screenshot where the constitutional transition gate applies. Do not flip cohort-wide Liquid or delete React from source presence alone.

## Governance decision boundary

Theme settings remain data (`THEME-R4`). Third-party app blocks/embeds, checkout extensions and new runtime roots are deferred (`NEVER-R3`, `ARCH-R2`). For literal merchant-executable Liquid, present a concrete proposed constitutional amendment to the human ARB; until then ship only the strongest safe data-only equivalent. Do not turn this editor work into a payment, custody, provider or checkout authority change.
