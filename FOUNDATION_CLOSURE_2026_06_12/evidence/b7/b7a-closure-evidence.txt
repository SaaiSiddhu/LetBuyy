Sub-step: Keyring model extension to internal-auth.ts

--- DESIGN SUMMARY ---
Added three exported helpers to services/api-gateway/src/lib/internal-auth.ts:

  getInternalApiKeyring(env: Env): Record<string, string>
    Parses INTERNAL_API_KEYRING JSON env var (callerId → HMAC secret map).
    Returns {} on unset, malformed JSON, non-object, or empty-value entries.

  isLegacyAcceptEnabled(env: Env): boolean
    Reads INTERNAL_AUTH_LEGACY_ACCEPT env var.
    Defaults ON (true) when unset or empty — non-breaking during rotation window.
    Explicitly disabled only by: "false" / "0" / "off" / "no" / "disabled".
    Sunset comment: disable after all callers provisioned + runtimes rotated (HR-SECRET-ROTATION).

  getSecretsForCaller(env: Env, callerId?: string | null): string[]
    Returns [keyring[callerId], ...legacySecrets] when caller has a keyring entry + legacy ON.
    Returns [keyring[callerId]] only when legacy OFF + caller has keyring entry.
    Returns [] when legacy OFF + no keyring entry for caller.
    Set-deduplicates output.

Updated verifyInternalAppRequest:
    Reads X-LetBuyy-Internal-Caller header (optional — no break if absent).
    Iterates getSecretsForCaller(c.env, callerId) instead of verifySignedPayload(c.env, ...).
    Returns true on first matching secret + consumes JTI.
    Backward-compatible: existing callers without the header use legacy secret pool.
