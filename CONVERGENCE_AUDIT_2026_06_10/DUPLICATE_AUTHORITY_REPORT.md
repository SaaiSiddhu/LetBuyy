## 2. Method

- **Authority framing.** For each domain: name **Authority A / B / C** by concrete path and state *what each claims to own*; then decide the single **Canonical Winner** (bound to `_PREMISES_SEED.md`), whether **Migration** is needed (Y/N + one-line path), and the loser's disposition — **Delete-now / Archive / Keep-temporarily** — plus a **Risk** rating.
- **Risk scale.** **S0** = user-facing money/identity/security exposure or law-mandates-its-own-loser; **S1** = security/integrity latent or blocks a winner from going live; **S2** = correctness/throughput/governance-honesty; **S3** = cleanup/cosmetic.
- **"Delete-now" gate.** Per the seed's convergence assumption ("no prod users/data/migration constraints" + aggressive-deletion), **Delete-now = YES only where the loser is dead code or pure documentation/config with no live consumer**. Where the loser is the *deployed* reality, or a winner is undeployed/unwired, or a validator mandates the loser, disposition is **Keep-temporarily** with the named blocking condition — deletion would break production or CI.
- **Convergence assumption (from seed §"Convergence assumption").** Phase 0 commits the working tree as the Truth Freeze and ratifies governance; many "migrations" below are therefore **DELETE-not-MIGRATE** once the only constraint was production safety.
- **Verification.** Every row cites a path verified this phase (grep/find/read) or a prior-report section spot-checked here. Live deployed state is UNVERIFIED throughout (repo evidence only; CI deploys from `main`).

## 5. Cross-cutting "Authority Multiplication" patterns

Three machines manufacture authorities faster than the canon retires them. Every per-domain conflict above is an instance of at least one.

1. **Temporal triplication (the master multiplier).** Because the canonical end-state lives only in the **uncommitted working tree**, every domain has **three simultaneous owners**: `main` (deployable, condemned), `HEAD` (interim), `working tree` (canonical, zero git history). The seed names this the master fact. Effect on *authority*: the winner this report names is, for every S0 row, the reality with the *least* durability — a `git checkout .`/`git clean -fd` would delete the winner and resurrect the losers. Resolution is structural: **Phase 0 commit + ratify**, avoiding the tracked-deletion/untracked-archive commit trap. Until then "which implementation is authoritative?" has no stable answer per domain.

2. **Validator aliasing (synthetic authority).** Verified this phase: **6 lane names → 1 validator** (`validate:distributed-execution/durable-execution/distributed-survivability/operational-certification/replay` → `no-scan-generated-agents-validator.mjs`) and `validate:migrations`≡`validate:rollback` → `migration-safety-validator.mjs`. Plus **5 assertions duplicated** across `whole-repo-end-state-validator.mjs` and the domain-owning validators. The pattern *fabricates the authority of coverage*: a green gate claims to certify distributed-execution / durable-execution / rollback safety while running an unrelated check. Worst instance — the **4-region assertion is asserted twice and both copies contradict the Constitution** (`:98,108,112`): the gate manufactures authority for an architecture its own supreme law voids (**S0 self-block**). Retargeting must be paired (`DEL-R3`) or the gate fails.

3. **Scan-AGENTS proliferation (authority by filename).** **38 nested generated `AGENTS.md`** + `docs/agents/AGENTS.md` ("central constitution") each become a *ranked local authority* by `CLAUDE.md:3` precedence ("local AGENTS.md" ordering) — even though the Constitution (`DOC-R1`/§5.4) says generated documents are never law. The anti-scan validators read **only root `AGENTS.md`** (`no-scan-generated-agents-validator.mjs:7`), so every nested copy is unpoliced. Generation is the multiplier: one generator run mints 38 local lawgivers, each authorizing whatever sprawl existed at scan time (e.g. `services/api-gateway/AGENTS.md` authorizing deleted `application-service` packages). The prompt families replicate the same way below-root (the `Codex_waves` factory mass-generates missions; `docs/` is outside the enforcement perimeter).
